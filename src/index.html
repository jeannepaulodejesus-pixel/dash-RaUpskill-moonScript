PressRun · Day 1: From Routine to Run

Follow one procedure from a plain checklist to a script you can run, read, and verify.

Begin

Repeated reporting requires us to repeat the same instructions.

Open, identify, select, prepare, check. Then again tomorrow, in the same order, by hand.

Automation starts with a procedure another person could follow.

Each vague word hides a business rule. A script cannot guess it, so we write it down.

    Keep the checklist. Write its executable twin beside it.

            An error becomes actionable when its location and cause are visible.
            
    
            
    
            
      
            
        
            KindWhat you seeWhere to look
            
        
          
            Syntax errorThe script will not save or run. A missing brace or quote.The editor marks the line before anything executes.
            
          
            Execution errorIt starts, then stops with a message and a line number.The execution log: message, function, Code.gs line.
            
          
            Incorrect resultIt completes. The output is wrong.Only an output check finds it. Try the lowercase status above.
            
                    
      
            
    
            
  
            

            



            
  
            
    
            Triggers change when a function runs and whose authority it uses.
            
    
            
      
            
        
            ExecutionWhen it runsRuns asKeep in mind
            
        
          
            ManualWhen you press Run, or choose a menu item you addedYouFirst run asks for authorization
            
          
            Simple triggerOn a fixed event such as onOpen or onEditThe person who caused the eventCannot use services that need authorization, such as Gmail. Short time limit.
            
          
            Installable triggerOn a schedule, a form submit, or a change you configureThe account that created the triggerScheduled runs happen within a window, not at an exact second. Ownership matters when people leave.
            
                    
      
            
    
            
  
            

            



            
  
            
    
            
      
            Reliable automation depends on controlled inputs and maintained rules.
            
    
            
    
              
      
            • Repeatabilityneeds validated inputs: sheet names, headers and status values checked before anything is written.
              • 
      
            • Integrationneeds permissions: the script acts with exactly the access it was granted.
              • 
      
            • Unattended executionneeds monitoring: failure notifications and a reviewed execution log.
              • 
      
            • Volumeneeds batch operations and respect for quotas: read once, write once. Current limits live in the quotas reference.
              • 
      
            • Rerunsneed safe replacement: clear, then write. Never append blindly.
              • 
      
            • Maintenanceneeds an owner who updates the rule when the reporting definition changes.
